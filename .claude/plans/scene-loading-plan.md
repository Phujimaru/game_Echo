# แผน: เข้าฉากด่านให้ลื่น (ไม่ตัดฉับ) — ECHO 5.1 ORDEAL CALL

> **อัปเดตหลัง 5.1.5 (ฉากเปิดแมตช์ใช้ลูกโลกร่วม) — จังหวะ mount กระดานเปลี่ยนแล้ว อ่านก่อนเริ่ม:**
> - ฉากเปิดแมตช์ทั้งหมด (`oc/intro/MatchIntro.jsx`) ใช้ลูกโลกร่วมใบเดิมต่อจากหน้าเลือกโหมด — `"gameintro"` อยู่ใน `GLOBE_SCREENS` (TransitionCurtain)
>   `SharedGlobeStage` จึงยังเปิดตลอดฉาก · ระหว่าง `showIntro` App **ไม่ render `<Game>` เลย** (`screen = null` — กระดานทึบจะบังฉากร่วม)
> - กระดาน mount ครั้งเดียวตอน `handoffIntro` = จังหวะชนผิวโลก (`0.82D + 0.1 ของช่วงเผย` หลังเริ่มดิ่ง ≈ X + 5.87 วิ เมื่อ D = 7 วิ) ใต้แฟลชขาวทึบ
>   พร้อมกันนั้นฉากร่วมปิด (canvas ถูกทำลาย) และ MatchIntro ถอด GlobeCanvas · แฟลช/แถบชื่อ (`.ocd`, z 65) จางเผยกระดานใน ~1 วิที่เหลือ
>   ไม่มีฉากดิ่ง (โหมดไม่มีการเดินทาง): ม่านขาว `.ocx-veil` ทึบ → mount กระดานที่ X+600ms → จางจบที่ X+1300ms
> - ผลคือ "กระดาน mount ใหม่ตอนฉากเปิดตัวจบ" (ข้อ 1 ด้านล่าง) ไม่มีแล้ว — มีแค่ mount ครั้งเดียวใต้แฟลช แต่ฉากหลังภูมิภาคยัง **วาดครั้งแรกตรงจังหวะเผยพอดี** (ข้อ 2/3 ยังเป็นงานค้าง)
>   ถ้าจะวาดฉากหลังล่วงหน้า ต้องวางไว้ใต้ฉากร่วมแบบไม่ทึบ หรือ mount ก่อนชนโดยซ่อนไว้ (opacity 0) — ห้ามให้ชั้นทึบบัง canvas ของฉากร่วม

> สถานะ: **วางแผนไว้ ยังไม่ได้ทำ** · ผู้ใช้จะให้อีก session รับผิดชอบ (2026-10-02)
> อ่านก่อน: `CLAUDE.md`, `.claude/HANDOFF.md` หัวข้อ C (5.1.x), `GAME_SYSTEM.md` ส่วนการเดินทาง

## ปัญหาที่ผู้ใช้เห็น
ฉากซูมดิ่งเข้าลูกโลกตอนเริ่มแมตช์ (`client/src/oc/intro/GlobeDive.jsx`) ผู้ใช้ชอบมาก ("เท่ๆมาก ทำได้ดี")
แต่พอจบแล้ว **ตัดเข้าฉากด่านแบบฉับพลัน** — ไม่รู้สึกว่า "ร่อนลง" ในภูมิภาคนั้นจริงๆ
ผู้ใช้อยากให้ "ฉากถูกโหลดแบบมีสไตล์" และอาจต้องปรับฉากพื้นหลังด้วย

## ต้นเหตุที่น่าจะเป็น (ต้องยืนยันก่อนแก้)
1. **กระดานถูก mount ใหม่ตอนฉากเปิดตัวจบ** — `App.jsx` สาขา `showIntro` คืน `<><Game/><GameIntro/></>`
   ส่วนสาขาปกติคืน `<Game/>` เดี่ยวๆ → โครงต้นไม้ React ต่างกัน → `<Game>` (5,700 บรรทัด + ฉากหลัง) ถูกถอดแล้วสร้างใหม่
   ตอน `finishIntro()` → เฟรมกระตุก/ฉากหลังเริ่มอนิเมชันใหม่ทั้งหมด
   (ฉากแผนที่การเดินทางวางนอก `screen` แล้วด้วยเหตุผลเดียวกัน — ดูคอมเมนต์ท้าย App.jsx)
2. **ฉากหลังภูมิภาคหนักตอนวาดครั้งแรก** — `journey/JourneyBackdrop.jsx` + `journey/scenes.jsx` (SVG ~1,400 บรรทัด, อนุภาค)
   ถ้ามันวาดครั้งแรกตรงจังหวะเผยฉาก จะกระตุกพอดี
3. **ไม่มีการเคลื่อนไหวต่อเนื่องระหว่าง "ชนผิวโลก" กับ "สนามรบ"** — overlay ของ GlobeDive แค่จางหายเผยกระดานที่อยู่นิ่ง
   ขนาด/มุมกล้องของกระดานไม่ได้ต่อจากการดิ่ง จึงดูเป็นการตัดภาพ
4. UI บนกระดาน (กรอบผู้เล่น มือไพ่ ปุ่มสกิล) โผล่พร้อมกันทั้งหมดทันทีที่ overlay หาย

## เป้าหมาย
- จังหวะชนผิวโลก → ภาพสนาม "ไหลต่อ" เหมือนกล้องร่อนลงมาในภูมิภาคนั้น ไม่มีจังหวะตัด
- ไม่มีเฟรมสะดุด (> ~50ms) ตั้งแต่เริ่มดิ่งจนกระดานพร้อมเล่น
- ใช้ได้กับฉากเปลี่ยนภูมิภาคทุก 10 เทิร์นด้วย (ฉากใหม่: ซูมออกไปลูกโลก → เส้นเดินทาง → ซูมกลับลง — ทำใน session นี้แล้ว จุดเผยฉากตอนจบควรใช้กลไกเดียวกัน)

## แนวทางที่เสนอ
1. **ทำให้ `<Game>` ไม่ถูก mount ใหม่** — ให้ App render `<Game>` ที่ตำแหน่งคงที่ (key คงที่) เสมอในทุกสาขาที่อยู่ในแมตช์
   แล้ววาง overlay (GameIntro / OrtArrival / GlobeDive / ฉากเปลี่ยนภูมิภาค) เป็นพี่น้องแยกชั้น
   ระวังเรื่อง `muteScenes` ที่ส่งให้ Game ระหว่างฉากเปิดตัว และ TransitionCurtain `skip()` ที่อ้าง screenKey
2. **วาดฉากหลังล่วงหน้าใต้ overlay** — ระหว่างฉากเปิดตัว/ดิ่ง ฉากหลังภูมิภาคปลายทางควร mount และวาดเสร็จไปแล้ว
   (ตอนนี้ Game ก็อยู่ข้างใต้อยู่แล้ว ถ้าข้อ 1 แก้ ฉากหลังจะไม่ถูกสร้างใหม่ตอนเผย) · พิจารณา decode รูปในฉากก่อน (`img.decode()`)
   และหยุดอนุภาคหนักๆ ไว้จนกว่าจะเผยเสร็จ
3. **ต่อกล้อง (camera continuity)** — ให้ GlobeDive ส่งสัญญาณ "จังหวะชน" (เช่น prop `onImpact` / event) ให้ชั้นสนาม:
   - ฉากหลังสนามเริ่มที่ scale ~1.2–1.3 + blur + แสงขาวจากจุดชน แล้วค่อยๆ ลงมา scale 1 / blur 0 ใน ~0.8–1.2 วิ
   - คลื่นกระแทก/แฟลชของ GlobeDive ซ้อนช่วงต้นของการลงจอด (crossfade ไม่ใช่ fade-to-cut)
   - ทิศ/จุดศูนย์กลางของการ scale ตรงกับจุดชนบนจอ (GlobeDive รู้ตำแหน่งจาก `core.project`)
4. **UI บนกระดานเข้าเป็นลำดับ** — หลังฉากหลังนิ่งแล้ว: แถบบน/ตัวจับเวลา → กรอบผู้เล่นทีละใบ → มือไพ่/ปุ่มสกิล (stagger 60–90ms)
   ห้ามทำให้ server รอเพิ่ม: เวลาที่ใช้ต้องอยู่ในช่วงที่ server พักเกมไว้แล้ว (`gameIntroHoldSeconds()` + `JOURNEY_START_SECONDS`)
   หรือเป็นอนิเมชันที่ไม่บังการกดเมื่อเทิร์นเริ่ม
5. **ฉากหลังภูมิภาค (ถ้าผู้ใช้อนุมัติให้ปรับ)** — ฉากปัจจุบันเป็นภาพแฟนตาซีสีสด (ปราสาท/ดอกไม้/ป่า ฯลฯ) ซึ่งผู้ใช้สั่งให้ "คงไว้" ใน 5.1
   ถ้าจะปรับ ให้ถามผู้ใช้ก่อนว่าต้องการลุคแบบไหน (เช่น ให้โทนเข้ากับลูกโลกขาว-ฟ้ามากขึ้น / ให้มีชั้นภาพที่ "ร่อนลง" ได้)

## เกณฑ์ผ่าน
- ดูด้วยตาในแอปจริง (exe dev: `cd desktop && ECHO_WINDOWED=1 npm start`) ตั้งแต่โหวตโหมด → ฉากเปิดตัว → ดิ่ง → สนาม ไม่มีจังหวะตัด/กระพริบ
- วัด long task / frame time ช่วงเผยฉาก (Performance panel ผ่าน CDP) ไม่มีเฟรมเกิน ~50ms
- โหมด lowQ และ prefers-reduced-motion ยังจบเร็ว/เรียบ
- `npm test` ผ่าน · eslint ไม่มี error ใหม่ · build ผ่าน
